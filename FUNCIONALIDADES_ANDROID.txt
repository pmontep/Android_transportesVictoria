1. LOGIN (AuthViewController)
---------------------------------------------------------------
Pantalla: Iniciar sesion
Rol: Cualquiera (sin autenticar)

Elementos UI:
- Logo TransportesVictoria
- Campo email
- Campo contrasena con boton "ojo" para mostrar/ocultar
- Boton "Iniciar sesion" (amarillo)
- ActivityIndicator
- Card con sombra contiene todos los elementos

Acciones:
- Validacion al perder foco: limpia bordes rojos al volver a escribir.
- Teclado se desplaza automaticamente para no tapar el boton.
- Tap "Iniciar sesion":
  * Valida que email y contrasena no esten vacios.
  * Si invalido: bordes rojos + alerta.
  * Si valido: POST /api/loginapi
    - 200: extrae token y rol, navega segun rol.
    - 401: "Correo o contrasena incorrectos".
    - 403: "Tu cuenta aun no ha sido activada por un reclutador".
    - Otro: "Error [codigo]. Intenta de nuevo".
  * Mientras carga: spinner + boton deshabilitado.
- Tap ojo: alterna isSecureTextEntry, cambia icono eye / eye.slash.

Navegacion:
- Entrante: primera pantalla (SceneDelegate).
- Saliente segun rol:
  * "usuario"    -> UsuarioTabBarController
  * "conductor"  -> ConductorTabBarController
  * "reclutador" -> ReclutadorTabBarController

2. REGISTRO (RegisterViewController)
---------------------------------------------------------------
Pantalla: Registro de cuenta
Rol: Cualquiera (sin autenticar)

Elementos UI:
- Titulo "Registro" + linea amarilla.
- Campos: Nombre, Apellidos.
- Picker Empresa (datos desde API).
- SegmentedControl: "Empleado" / "En entrenamiento".
- Carnet (visible solo si Empleado).
- DPI (visible solo si En entrenamiento).
- Telefono (phonePad).
- Correo (emailAddress).
- Direccion (texto libre).
- Picker Departamento (22 departamentos de Guatemala).
- Switch "Acepto los acuerdos de uso" con link azul subrayado.
- Boton "Registrar" (azul).
- Boton "Inicia sesion" en pie (vuelve atras).

Comportamientos:
- Cambio en segmented:
  * 0 (Empleado): muestra carnet, oculta DPI.
  * 1 (Entrenamiento): oculta carnet, muestra DPI.
  * Transicion animada (UIView.animate).
- Link "acuerdos de uso" -> TerminosViewController (push si hay nav, modal si no).
- Carga inicial de empresas: GET /api/empresas (sin auth).
  * Placeholder "Cargando empresas..." -> "Error al cargar empresas" si falla.
  * Preselecciona la primera empresa.
  * Picker muestra nombre_corto, guarda idL internamente.

Validacion al registrar:
- Obligatorios: nombre, apellidos, telefono (8+ digitos, solo numeros),
  correo (formato), direccion, departamento, empresa.
- Si Empleado: carnet obligatorio.
- Si Entrenamiento: DPI obligatorio.
- Switch acuerdos: si OFF -> alerta "Debes aceptar los acuerdos de uso".
- Campos invalidos: borde rojo 1.5px + shake.

Envio POST /api/loginRegister con body:
  name, lastname, email,
  tipo_usuario ("1" empleado | "0" entrenamiento),
  empresa_idL, departamento, direccion, telefono,
  accepted_terms: true,
  carnet (si empleado) | dpi (si entrenamiento)

Respuestas:
- 201: pop al Login con mensaje "Tu cuenta esta en espera de activacion...".
- 422: "El correo ya esta registrado o hay un campo invalido".
- 403: "La empresa seleccionada no esta activa. Contacta a tu reclutador".
- Otro: usa message del JSON.

Navegacion:
- Entrante: desde Login (push).
- Saliente: pop a Login (link o registro exitoso).

4. DETALLE VIAJE - CONDUCTOR (DetalleViajeViewController)
---------------------------------------------------------------
Pantalla: Detalle del viaje
Rol: Conductor

Elementos UI:
- Navigation bar amarillo + titulo + icono bus.fill (decorativo).
- ScrollView con:
  * Card info: Ruta, Fecha, Hora, Estado, Total Pasajeros.
  * Boton "Iniciar viaje" (amarillo si estado "programado").
  * Boton "Finalizar viaje" (amarillo si "en curso", gris si "completado").
  * Titulo "Pasajeros".
  * TableView embebida sin scroll interno.
- ActivityIndicator.

Celda PasajeroCell:
- Nombre y apellido, correo, telefono.
- Checkbox "Abordar" si no abordado.
- Hora de abordaje en gris si ya abordado.
- Boton "Ver en mapa" si tiene lat/lng.

Reglas de estado:
- "programado": Iniciar viaje activo, Finalizar gris.
- "en curso" / "iniciado": Finalizar activo.
- "completado" / "finalizado": ambos botones grises, tabla bloqueada.

Acciones:
- Iniciar viaje:
  * Confirmacion "Iniciar viaje? El viaje comenzara ahora."
  * PATCH /api/conductor/viajes/{idL}/iniciar.
  * 200: estado -> "En curso", refresca UI.
  * Falla: revierte UI + alerta.
- Finalizar viaje:
  * Confirmacion "Finalizar viaje? Se marcara como completado."
  * PATCH /api/conductor/viajes/{idL}/finalizar.
  * 200: estado -> "Completado".
- Abordar pasajero (toggle):
  * Cambio optimista en UI.
  * PATCH /api/conductor/solicitud/{solicitudId}/abordar.
  * 200: si paso a abordado, asigna hora actual (HH:mm). Refresca celda.
  * Falla: revierte. Si mensaje contiene "finalizado"/"modificar":
    "Viaje completado. No se puede modificar la lista". Otro: "Sin conexion...".
- Ver en mapa (pasajero):
  * Push MapaUbicacionViewController con lat, lng, nombre completo y direccion.
  * Sin boton "Abrir en Apple Maps".

Navegacion:
- Entrante: push desde ViajesAsignadosViewController.
- Saliente: push a MapaUbicacionViewController.

- Confirmacion "Desactivar usuario?" / "Activar usuario?" con "[Nombre] [Apellido]".
- Si confirma:
  * Cambio optimista en UI.
  * PATCH /api/reclutador/usuarios/{id}/toggle-status.
  * 200: si el filtro actual ya no incluye al usuario, lo quita de la lista.
  * Falla: revierte UI + alerta "No se pudo cambiar el estado".
  * Actualiza contador.

7. CREAR SOLICITUD DE VIAJE - USUARIO (CreaSolicitudViewController)
---------------------------------------------------------------
Pantalla: Solicitar viaje
Rol: Usuario

Elementos UI:
- Titulo "Solicitar viaje" (nav bar).
- Campo Ruta: inputView UIPickerView, accesoryView con boton "Listo".
  * Si una ruta: pre-selecciona y deshabilita.
  * Si varias: permite elegir.
  * Label de error rojo si vacio al enviar (shake).
- Campo Hora: picker dependiente de la ruta.
- Campo Observaciones (opcional).
- Boton "Enviar" (azul). Se habilita con ruta Y hora.

Flujo:
1. Toca campo Ruta -> GET /api/viajes/mis-rutas (Bearer).
   * 200: lista de rutas.
   * 403: "No tienes rutas asignadas".
   * 401: "Sesion expirada".
   * 404: "Endpoint no encontrado".
   * Otro: "Error del servidor".
2. Selecciona ruta -> cargarHorariosDeRuta(nombreRuta).
3. GET /api/viajes/horarios?ruta=[nombreRuta] (Bearer).
   * 200: lista de horas.
   * 403: "La ruta no esta asignada a tu perfil".
   * Otro: "No se pudieron cargar los horarios".
4. Selecciona hora.
5. Ingresa observaciones (opcional).
6. Tap "Enviar" -> POST /api/viajes/solicitar.
   * Body: rutaSolicitada, horaSolicitud, observaciones (si hay).
   * 200/201: aviso "Solicitud enviada" + pop.
   * 409: "Solicitud duplicada".
   * 400 segun error_code:
     - HORARIO_CERRADO: "El horario de solicitudes ya cerro (17:00)".
     - HORARIO_NO_INICIADO: "El horario aun no ha abierto".
     - HORA_INVALIDA: "La hora seleccionada no esta disponible para esta ruta".
   * 403: "Esta ruta no esta asignada a tu perfil".

Navegacion:
- Entrante: push desde UsuarioViewController.
- Saliente: pop al anterior (cancelar o enviar exitoso).

8. DETALLE SOLICITUD - USUARIO (DetalleSolicitudViewController)
---------------------------------------------------------------
Pantalla: Detalle de solicitud de viaje
Rol: Usuario

Elementos UI:
- Logo pequeno + linea amarilla.
- Boton atras (chevron.left).
- Titulo + boton refresh.
- Badge de estado (verde=activa, rojo=cancelada, gris=otro).
- Card "Datos del viaje": Ruta, Estado viaje, Abordo (Si/No), Observaciones.
- Card "Informacion de la solicitud": Solicitado el, Estado.
- Card "Tu calificacion" (solo si viaje completado):
  * Si calificado: estrellas + comentario.
  * Si no: boton "Calificar viaje" (amarillo).
- Boton "Cancelar solicitud" (rojo): visible si estado solicitud NO es "completado/cancelada".
- Boton "Volver a mis solicitudes" (negro).

Estados:
- Solicitud (normalizado):
  * activa/pendiente/confirmada: badge verde, boton cancelar visible.
  * cancelada/cancelado/rechazado: badge rojo, boton cancelar oculto.
- Viaje:
  * completado: muestra card calificacion + oculta boton cancelar.

Acciones:
- Refresh: GET /api/viajes/mis-solicitudes/{idL}.
- Calificar viaje: presenta CalificarViajeViewController modal (pageSheet con grabber)
  con onCompletado callback que actualiza UI optimista + refetch.
- Cancelar solicitud:
  * Muestra ConfirmarCancelacionViewController.
  * Si confirma: DELETE /api/viajes/mis-solicitudes/{idL}.
    - 200/204: muestra CancelacionExitosaViewController, al tocar "Entendido" hace pop.
    - Falla: alerta + boton rehabilitado.

Navegacion:
- Entrante: push desde UsuarioViewController o SolicitudesViewController.
- Saliente: pop al anterior.

    - 200: cierra modal + onCompletado(calificacion, comentario).

- Cancelar: dismiss sin guardar.

- Entrante: modal desde DetalleSolicitudViewController.

15. RECUPERAR CONTRASENA (RecuperarContrasenaViewController)
---------------------------------------------------------------
Pantalla: Recuperar contrasena
Rol: Sin autenticar
Flujo de 3 pasos en una misma vista, con indicador de pasos (Correo / Codigo / Contrasena).

Paso 1 - Ingresa email:
- Campo email.
- Boton "Enviar codigo".
- POST /api/forgot-password con { email }.
  * 200: banner amarillo "Codigo enviado a [email]" (2.5s) -> Paso 2.
  * 422: "Correo invalido".
  * 500: "No pudimos enviar el correo".

Paso 2 - Verifica codigo OTP:
- Campo monospace centrado (kerning 8pt), placeholder "------", numberPad, max 6 digitos.
- Boton "Verificar codigo" deshabilitado hasta 6 digitos.
- POST /api/verify-otp con { email, code }.
  * 200 y valid=true: Paso 3.
  * 200 y valid=false: "El codigo es invalido o ha expirado".
  * 400: "Codigo invalido".

Paso 3 - Nueva contrasena:
- Campos "Nueva contrasena" y "Confirmar contrasena" (8+ caracteres).
- Boton "Cambiar contrasena".
- POST /api/reset-password con { email, code, password, password_confirmation }.
  * 200: alerta "Contrasena actualizada! Inicia sesion con tu nueva contrasena" + pop al Login.
  * 400: "Codigo invalido o expirado".
  * 404: "Usuario no encontrado".
  * 422: "Las contrasenas no son validas".

Teclado:
- Listeners de show/hide. Si tapa el boton, desplaza vista hacia arriba (animado).
- Tap fuera oculta teclado.

Navegacion:
- Entrante: desde Login.
- Saliente: pop si hay anterior, dismiss si no.

18. ENDPOINTS HTTP UTILIZADOS

AUTENTICACION Y SESION

  Body: email, password

REGISTRO

  Body: name, lastname, email, tipo_usuario (0/1), empresa_idL,

PERFIL

- POST /api/perfil/foto     multipart "foto". 200 { profile_photo_url }.

                            password_confirmation }. 200 ok;
                            400 error_code WRONG_PASSWORD; 422 validacion.

SOLICITUDES DE VIAJE (Usuario)
- GET    /api/viajes/mis-solicitudes?page=1&query=   Bearer -> { data: [Solicitud] }.
- GET    /api/viajes/mis-solicitudes/{idL}           Bearer -> { solicitud } o Solicitud directa.
- POST   /api/viajes/solicitar                       Bearer. Body { rutaSolicitada,
                                                     horaSolicitud, observaciones? }.
                                                     200/201 ok; 409 duplicada;
                                                     400 con error_code HORARIO_CERRADO /
                                                     HORARIO_NO_INICIADO / HORA_INVALIDA;
                                                     403 ruta no asignada.
- PATCH  /api/viajes/mis-solicitudes/{idL}/calificar Bearer. Body
                                                     { calificacion, comentario_calificacion? }.
- DELETE /api/viajes/mis-solicitudes/{idL}           Bearer. 200/204 ok.

RUTAS Y HORARIOS (Usuario)
- GET /api/viajes/mis-rutas               Bearer -> { rutas: [...] }.
                                          401 sesion; 403 sin rutas; 404 endpoint.
- GET /api/viajes/horarios?ruta=[nombre]  Bearer -> { horarios: ["HH:mm", ...] }.
                                          403 ruta no asignada.

VIAJES (Conductor)
- GET   /api/conductor/viajes[?fecha=YYYY-MM-DD]                 Bearer -> { data: [Viaje] }.
- PATCH /api/conductor/viajes/{idL}/iniciar                       Bearer.
- PATCH /api/conductor/viajes/{idL}/finalizar                     Bearer.
- PATCH /api/conductor/solicitud/{solicitudId}/abordar            Bearer.

USUARIOS (Reclutador)

RECUPERACION DE CONTRASENA (sin auth)
- POST /api/forgot-password   { email }                    -> { message }.
- POST /api/verify-otp        { email, code }              -> { message, valid }.
- POST /api/reset-password    { email, code, password,
                                password_confirmation }    -> { message }.

Convenciones:
- Headers comunes: Accept: application/json y Content-Type: application/json (cuando hay body).
- Headers protegidos: Authorization: Bearer [token].


---------------------------------------------------------------
19. NOTAS IMPORTANTES PARA IMPLEMENTACION ANDROID
---------------------------------------------------------------

NAVEGACION
- Login es entry point.
- Tras autenticar, no se vuelve a Login con back (cambia el rootViewController).
- Cada rol tiene su tab bar. Dentro de cada tab hay un nav stack.

SESION
- SessionManager guarda token y currentUser en memoria.
- En Android: usar DataStore o EncryptedSharedPreferences.
- Persistir el token entre sesiones segun politica del proyecto.

AUTORIZACION
- Header Authorization: Bearer [token] en todos los endpoints protegidos.
- Sin token = no llamar a endpoints protegidos; en Android, interceptor de OkHttp.

VALIDACIONES (cliente)
- Email con @ y punto.
- Telefono 8+ digitos numericos.
- Contrasena 8+ caracteres.
- Codigo OTP 6 digitos numericos.
- Campos invalidos: borde rojo + animacion shake.

LOADERS
- ActivityIndicator durante llamadas (CircularProgressIndicator en Compose).
- Pull-to-refresh en listas (SwipeRefreshLayout o pullRefresh modifier).
- Botones deshabilitados con opacidad reducida durante operacion.
- Icono refresh con rotacion continua (animateFloat con tween infinite).

DEBOUNCE
- Busqueda de usuarios: 0.3s.

OPTIMISMO UI
- Toggle activo/inactivo (reclutador) y abordar pasajero (conductor):
  cambiar UI primero, revertir si falla. Mejora UX percibido.

DEDUPLICACION
- En Mis Solicitudes (usuario) se deduplica por idL en cliente.

ERRORES HTTP - CONVENCIONES
- 401 sesion: forzar logout o pedir re-login.
- 403: mensajes contextuales (no activada / ruta no asignada / viaje finalizado).
- 404: "Endpoint no encontrado".
- 409: solicitud duplicada (mismo dia).
- 422: validacion del servidor (usar message del JSON).
- 500: error generico del servidor.
- 400 con error_code en body: usar codigo para mensajes especificos
  (HORARIO_CERRADO, HORARIO_NO_INICIADO, HORA_INVALIDA, WRONG_PASSWORD).
